# Yuki Core

Сервер («мозг») экосистемы Yuki. Написанный на Python `asyncio` WebSocket-сервер, который
аутентифицирует устройства, маршрутизирует команды, передаёт сообщения между устройствами,
собирает метрики и обслуживает канал реального времени, к которому подключается панель
управления `yuki-webui`.

## Требования

Python 3.10+, зависимости зафиксированы в `requirements.txt` (`websockets==16.0`, `psutil==7.2.2`).

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python core.py
```

По умолчанию сервер слушает `ws://0.0.0.0:8000` по двум путям: `/device` (для `yuki-humidifier`,
`yuki-device-pc`, `yuki-device-pc-linux`, `yuki-device-android`) и `/webui` (для браузерной панели
управления `yuki-webui`).

## Конфигурация (переменные окружения)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `YUKI_AUTH_TOKEN` | (генерируется автоматически) | Общий токен аутентификации устройств. Если не задан, при первом запуске генерируется случайный 32-символьный токен, сохраняется в `.token` (права доступа 600) и ротируется по расписанию ниже. |
| `YUKI_TOKEN_ROTATION_HOURS` | `24` | Как часто ротируется автоматически сгенерированный токен. Игнорируется, если задан `YUKI_AUTH_TOKEN`. |
| `YUKI_DEBUG` | не задано | Если задано, при неожиданных ошибках соединения выводится полная трассировка стека вместо однострочного сообщения в лог. |
| `YUKI_TLS_ENABLED` | не задано | Если значение "истинно" (`1`/`true`/`yes`), сервер работает по `wss://` вместо `ws://` - также требует `YUKI_TLS_CERT`/`YUKI_TLS_KEY`. |
| `YUKI_TLS_CERT` / `YUKI_TLS_KEY` | не задано | Пути к PEM-сертификату/ключу, используемые при включённом `YUKI_TLS_ENABLED`. |

Шифрование **по умолчанию отключено** во всей экосистеме; чтобы включить его для связи
core↔device/webui, задайте все три переменные `YUKI_TLS_*` одновременно.

## Файлы данных

Все хранятся рядом с `core.py`: `yuki_core.db` (SQLite - известные устройства, авторизация, чёрный
список, история метрик, журнал аудита), `.token`/`.token_meta` (текущий токен аутентификации и время
его создания, права доступа 600), `logs/` (по одному лог-файлу на запуск).

## Авторизация устройств

Устройство, предъявившее корректный `auth_token`, не становится доверенным автоматически - если
его ещё нет в списке авторизованных устройств, `yuki-core` запрашивает у подключённых клиентов
`yuki-webui` разрешение на его подключение (`device_auth_request`/`device_auth_response`), прежде
чем завершить рукопожатие. Устройства также можно занести в чёрный список - это отклоняет
соединение безусловно, независимо от токена.

## Протокол

Использует Yuki Protocol `yuki/1.0` через встроенную копию в `libs/yuki-protocol/python/` - сам
формат сообщений описан в [`yuki-protocol`](../yuki-protocol).
